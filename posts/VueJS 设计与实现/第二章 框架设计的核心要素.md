## 提升用户的开发体验

衡量一个框架是否足够优秀的指标之一就是看它的开发体验如何

```js
createApp(App).mount('#not-exist')
```

当我们创建一个Vue.js应用并试图将其挂载到一个不存在的DOM节点时,就会收到一条警告信息:

<code style="color: #b45309; background-color: #fef3c7; border: 1px solid #f59e0b;">
[Vue warn]: Failed to mount app: mount target selector "#not-exist" returned null.
</code>

这条警告信息清晰地指出了问题所在:我们试图将应用挂载到一个不存在的DOM节点上

试想一下,如果Vue.js内部不做任何处理,那么我们很可能得到的是JavaScript层面的错误信息,例如:

<code style="color: red; background-color: #fdd; border: 1px solid red;">
TypeError: Cannot read property 'appendChild' of null
</code>

始终提供友好的警告信息不仅能够帮助用户快速定位问题,节省用户的时间和精力,还能够提升用户的开发体验,让用户更愿意使用我们的框架

## 控制框架代码的体积

框架的大小也是衡量框架的标准之一

同样的功能,用的代码越少越好,但是提供完善的警告信息意味着我们需要在框架中包含更多的代码来处理各种边界情况,这可能会增加框架的体积
因此,我们需要想办法解决这个问题

如果我们去看Vue.js的源码,就会发现每一个warn函数的调用都会配合`__DEV__`常量的检查,例如:

```js
if (__DEV__ && !res) {
  warn(`Failed to mount app: mount target selector "${selector}" returned null.`)
}
```

可以看到,打印警告信息的前提是`__DEV__`为true

Vue.js在输出资源的时候会输出两个版本,其中一个用于开发环境,如`vue.global.js`,另一个用于生产环境,如`vue.global.prod.js`

当Vue.js构建用于生产环境的版本时,会将`__DEV__`替换为false

```js
if (false && !res) {
  warn(`Failed to mount app: mount target selector "${selector}" returned null.`)
}
```

这时我们发现这段分支代码永远都不会执行,称为`dead code`,它不会出现在最终产物中,在构建资源的时候就会被移除,因此在`vue.global.prod.js`中就不会存在这段代码,从而减少了框架的体积

## 框架要做到良好的Tree-Shaking

什么是Tree-Shaking呢?

简单来说,Tree-Shaking指的就是消除那些永远不会被执行的代码,也就是排除 `dead code`

想要实现Tree-Shaking,必须满足一个条件,即模块必须是ESM(ES Module),因为Tree-Shaking依赖ESM的静态结构

我们以rollup.js为例,来看看Tree-Shaking是如何工作的,其目录结构如下

```
├── demo
│   ├── package.json
│   └── input.js
│   └── utils.js
```

首先按安装rollup.js

```bash
pnpm init
pnpm i rollup -D
```

下面是`utils.js`和`input.js`的内容

```js
// input.js
import { foo } from './utils.js'
const obj = {}
foo(obj)
```

```js
// utils.js
export function foo(obj) {
  obj && obj.foo()
}
export function bar(obj) {
  obj && obj.bar()
}
```

我们在`input.js`中只导入了`foo`函数,而没有导入`bar`函数

接着,我们执行以下命令来构建资源

```bash
npx rollup input.js -f esm -o bundle.js
```

这句命令的意思是,以`input.js`作为输入文件,输出一个ESM格式的模块,并将结果写入`bundle.js`

```js
// bundle.js
function foo(obj) {
  obj && obj.foo()
}
const obj = {}
foo(obj)
```

可以看到,其中并不包含bar函数,说明Tree-Shaking起了作用

由于我们并没有使用bar函数,因此它作为`dead code`被移除了

foo函数虽然被调用了,但是这段代码仅仅是读取对象的值,所以它的执行似乎没什么必要,为什么它没有被移除呢?

这就涉及到Tree-Shaking的一个重要概念,即`副作用(side effect)`

如果一个函数调用会产生副作用,那么就不能将其移除

什么是副作用?简单来说,副作用就是当调用函数时会对外部产生影响,例如修改了全局变量

在这个例子中,foo函数虽然没有修改全局变量,但是它读取了obj的值,如果obj是一个通过`Proxy`创建的代理对象,那么读取obj的值就会触发代理对象的`get`方法,从而产生副作用

```js
const obj = new Proxy(
  {},
  {
    get(target, key) {
      // 这里会有副作用
    },
  },
)
foo(obj)
```

至于到底会不会产生副作用,只有代码运行的时候才知道,JavaScript本身是动态语言,因此想要静态地分析哪些代码是`dead code`是非常困难的

但是像 rollup.js 这类的工具都会提供一个机制,让我们能明确地告诉 rollup.js 可以去移除它

```js
import { foo } from './utils.js'
const obj = {}
/*#__PURE__*/ foo(obj)
```

在函数调用前面添加`/*#__PURE__*/`注释,就告诉rollup.js这个函数调用是一个纯函数调用,它没有副作用,因此当它的返回值没有被使用时,就可以将其移除

此时再次执行构建命令并查看`bundle.js`的内容,就会发现它是空的
