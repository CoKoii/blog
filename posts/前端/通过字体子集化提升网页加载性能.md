## 前言

中文 Web 字体体积通常很大，完整字体往往包含上万个字形。但单个页面实际只会用到其中一小部分字符。  
直接加载整包字体会拖慢首屏渲染，影响阅读体验和 LCP。

字体子集化的思路很简单：  
把完整字体按字符范围切成多个小文件，让页面按需加载真正用到的字形。

## 实测数据

测试场景：

- 同局域网下另一台设备
- 页面内容为一篇《红楼梦》长文（字符种类非常多）
- 对比「未切分字体」与「切分后字体」的加载耗时

测试结果：

| 方案           | 字体加载耗时 |
| -------------- | ------------ |
| 未启用字体切分 | 2.47 秒      |
| 启用字体切分   | 1.07 秒      |

结论：耗时减少 1.40 秒，按数据计算约下降 56.7%。

这组数据属于偏极端场景：  
《红楼梦》单篇文章字符覆盖非常广，正常网页的字符种类通常不会比它更多。  
因此在普通内容页里，字体子集化带来的性能收益通常不会比这个场景更差。

## 接入步骤

以开源字体 [LXGW WenKai](https://github.com/lxgw/LxgwWenKai) 为例：

1. 安装 `font-slice`

```bash
npm install --save-dev font-slice
```

2. 下载字体文件 `LXGWWenKai-Light.ttf`

3. 编写切分脚本 `slice-font.js`

```js
const createFontSlice = require('font-slice')
const path = require('path')

createFontSlice({
  // 字体文件路径
  fontPath: path.resolve(__dirname, 'LXGWWenKai-Light.ttf'),
  // 输出目录
  outputDir: path.resolve(__dirname, './dist'),
})
```

4. 执行切分

```bash
node slice-font.js
```

5. 查看产物（示例）

- `font.css`
- `index.html`（预览页）
- `LXGWWenKai-Light.1.woff2`
- `LXGWWenKai-Light.2.woff2`
- `LXGWWenKai-Light.3.woff2`
- ...

6. 将生成的 `font.css` 和 `woff2` 文件复制到项目静态目录（如 `public/fonts`）

7. 在项目中引入并应用字体

```css
@import './fonts/font.css';

body {
  font-family: 'LXGWWenKai-Light';
}
```

## 结语

字体子集化可在不改变视觉效果的前提下，显著降低中文 Web 字体加载成本。  
实测极端字符场景下，字体加载时间由 2.47 秒降至 1.07 秒，降幅约 56.7%。  
对以中文内容为主的站点，该方案具备明确的性能收益与较高的落地价值。
